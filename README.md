# Typora Canvas

A Canvas rendering plugin for Typora, exploring smooth large-document rendering while gradually improving editing and native feature compatibility.

**Current release: [v0.6.14](https://github.com/Ling0727-ai/typora-canvas/releases/tag/v0.6.14).** Prebuilt ZIP and npm packages are available; no local compilation is required. The plugin includes hybrid mode and an experimental pure Canvas editor. The pure Canvas editor uses its own Markdown source model, layout, caret, and selection, drawing document content into a viewport Canvas. Callouts can reuse local image caches generated by the installed Callouts plugin. Everything stays inside the existing editor pane.

## Quick start

First install and enable the [Typora plugin framework](https://github.com/obgnail/typora_plugin#how-to-use-windowslinux-platform). With Node.js installed, run:

```bash
npm install -g @ling0727-ai/typora-canvas@latest
typora-canvas --mode canvas-editor --dry-run
typora-canvas --mode canvas-editor
```

Save your notes and fully restart Typora. npm installs the CLI; the CLI command without `--dry-run` deploys the prebuilt plugin to Typora. The default resource path is `C:\Program Files\Typora\resources`; Linux and custom installations need `--resources "/actual/resource/directory"` on both CLI commands. Writing a protected directory requires an appropriately privileged terminal. For ZIP installation without Node.js and platform details, see [Installation and updates](#installation-and-updates).

Use `--mode canvas-editor` for the editable Canvas mode. A first installation without `--mode` uses hybrid mode, which keeps native editing and caches static content. `Ctrl+Alt+Shift+F8` toggles the plugin; `Esc` leaves the pure Canvas editor. See [mode configuration](#enable-and-choose-a-mode) for automatic opening and switching modes.

## Recent changes

- **0.6.14:** structural edits now retire Callout captures at obsolete source-line positions, including pending captures. Inserting list items and undoing/redoing no longer accumulate stale cache entries; valid previews remain cached. Browser coverage repeats five redo/undo cycles, and failed runs include editor statistics.
- **0.6.13:** empty unordered items render bullets; Enter continues, splits, or exits a list. Ordered numbering updates subsequent siblings in the current list level and container. Decimal, alphabetic, Roman, and parenthesized markers are supported, along with mixed nested lists, code blocks, quotes, and Callouts.
- The 0.6.14 main-branch and release workflows passed on Windows, macOS, and Linux, including unit tests, packaged installation, and Chromium regressions. The release workflow publishes ZIP/npm archives to GitHub Releases and the same prebuilt tarball to npm using OIDC trusted publishing. Real Typora installation and host compatibility remain subject to the [platform scope](#requirements-and-platform-scope).

## Choose a mode and explore features

| Mode | Editing and rendering | Use case |
| --- | --- | --- |
| `canvas-editor` | Independent source, caret, and selection; viewport Canvas drawing | Try large-document editing within the compatibility limits below |
| `hybrid` | Native Typora editing with static Canvas caching | Keep native interactions and complex plugins as a compatibility baseline |
| `canvas` | Early standalone read-only viewer | Reading without editing |

The pure Canvas editor supports mixed nested lists, formulas, basic tables and keyboard commands, Callouts, sampled theme styles, Obsidian images, outline navigation, and regex search. See [features and architecture](docs/FEATURES.md) for behavior, shortcuts, and limits.

Arbitrary theme CSS, footnotes, HTML, custom macros, complex tables, and other plugins depending on the native DOM need individual adaptation. Unsupported syntax retains its source; `Esc` returns to native editing. Save bridging has primarily been verified with Windows Typora 1.14. Hybrid performance gains need measurement in real notes.

## Installation and updates

### Requirements and platform scope

- For ZIP installation, no Git or Node.js is required. The npm CLI needs Node.js; version 22 is recommended (minimum 20). Git is needed only for source builds.
- First install and enable [obgnail/typora_plugin](https://github.com/obgnail/typora_plugin#how-to-use-windowslinux-platform). Verify that its plugins work after restarting Typora. This project's installer installs only the Canvas extension; it does not inject the framework.
- The target must be the **resource directory already containing `plugin/global/core/index.js`**, not the theme directory or the `plugin` directory itself. This is usually the directory containing `window.html`; older versions may use `resources/app`. The installer also checks that the framework's `[global].ENABLE` setting is enabled.

| Platform | Installation | Verification scope |
| --- | --- | --- |
| Windows | Defaults to `C:\Program Files\Typora\resources`; override with `--resources` | CI passes; real host testing has primarily used Windows Typora 1.14 |
| Linux | Pass the existing framework resource directory with `--resources`; the path depends on the package | Build, unit tests, and Chromium CI pass; real Typora testing is still needed |
| macOS | Upstream currently documents Windows/Linux installation; this project has no verified macOS Typora installation procedure | Build, unit tests, and Chromium CI pass; the browser demo is available |

**Passing CI on three operating systems does not establish Typora installation support on all three.** Do not use the Windows default path on macOS or assume that copying files into an application bundle loads the framework.

### Install a prebuilt release (no local compilation)

**ZIP, without Node.js:** download `typora-canvas-v0.6.14.zip` from [Releases](https://github.com/Ling0727-ai/typora-canvas/releases/latest). Extract and copy **both** `canvas_reader.js` and the complete `canvas_reader/` folder into your existing framework's `plugin/` directory. Replace both when updating. Do not create another nested `plugin` folder. Retain a copy of old files/settings; manual copying does not run automatic backups. Enable `[canvas_reader]` using the [configuration example](#enable-and-choose-a-mode) and fully restart Typora. Preserve other plugins' settings in the same file.

**npm, with Node.js but no compilation:**

```bash
npm install -g @ling0727-ai/typora-canvas@latest
typora-canvas --mode canvas-editor --dry-run
typora-canvas --mode canvas-editor
```

The CLI defaults to the Windows resource path. Linux and custom installations must specify their existing framework directory:

```bash
typora-canvas --resources "/actual/resource/directory" --mode canvas-editor --dry-run
typora-canvas --resources "/actual/resource/directory" --mode canvas-editor
```

You can also use `npm install -g ./ling0727-ai-typora-canvas-0.6.14.tgz` with a downloaded archive. The package includes the compiled plugin and a bundled installer, with no runtime npm dependencies or build/install lifecycle scripts. npm installs the command; **run `typora-canvas` explicitly to deploy it to Typora**, then fully restart Typora. Framework prerequisites and directory write permissions still apply. Use `typora-canvas --help`, `--version`, or `--uninstall`; pass the same `--resources` when disabling. Installing a newer `.tgz` updates the CLI; run it again to update Typora's copy. `npm uninstall -g @ling0727-ai/typora-canvas` only removes the CLI, so disable the deployed plugin first if desired.

The public npm package is [`@ling0727-ai/typora-canvas`](https://www.npmjs.com/package/@ling0727-ai/typora-canvas). Use the scoped name; the unscoped `typora-canvas` package is not this distribution. To pin a version, use `@ling0727-ai/typora-canvas@0.6.14`. A release tarball URL remains an alternative, for example `https://github.com/Ling0727-ai/typora-canvas/releases/download/v0.6.14/ling0727-ai-typora-canvas-0.6.14.tgz`. macOS host installation remains unverified as described above. Git and development dependencies are only needed for the source route below; ZIP installation needs neither Git nor Node.js.

### Build from source (optional)

To change the plugin or test unreleased commits, follow [build and validation instructions](docs/DEVELOPMENT.md). ZIP/npm users can install without Git, cloning, or a build step.

### Enable and choose a mode

`--dry-run` checks the framework, configuration, and build files and prints the selected paths without writing installation files. Once those paths are correct, run without `--dry-run`, save your notes, and **fully quit and reopen Typora**. The installer does not close Typora automatically.

| `--mode` / `RENDER_MODE` | Behavior |
| --- | --- |
| `canvas-editor` | The editable pure Canvas experiment described here |
| `hybrid` | Native editing with static Canvas caching; the first-install default when no mode is specified |
| `canvas` | The early standalone read-only viewer |

On updates, omitting `--mode` preserves an existing `canvas-editor` or `canvas` mode; otherwise it uses `hybrid`. Pass the desired mode explicitly to make the choice clear. An existing `AUTO_OPEN = false` is preserved.

Before installation, backups go to `~/.config/typora-canvas/backups/`. If `~/.config/typora_plugin/settings.user.toml` exists, the installer edits it; otherwise it uses the framework directory's user settings. It does not rewrite Typora's `window.html`.

The installer maintains the `[canvas_reader]` section. For manual changes, edit the existing section in the configuration file printed by the installer; do not add duplicate sections. This example enables the pure Canvas editor:

```toml
[canvas_reader]
ENABLE = true
NAME = "Typora Canvas"
HOTKEY = "ctrl+alt+shift+f8"
AUTO_OPEN = true
RENDER_MODE = "canvas-editor"
CACHE_MB = 24
```

Set `AUTO_OPEN = false` for manual activation. `Ctrl+Alt+Shift+F8` toggles the plugin, and Escape returns from pure Canvas to native editing. `CACHE_MB` controls hybrid caching, not every pure Canvas asset cache.

### Update or disable

For npm installations:

```bash
npm install -g @ling0727-ai/typora-canvas@latest
typora-canvas --mode canvas-editor --dry-run
typora-canvas --mode canvas-editor
```

Use the same `--resources` as before when needed, then fully restart Typora. Check the CLI version with `typora-canvas --version`. To disable the deployed plugin, run `typora-canvas --uninstall` with that resource path and restart Typora. Removing the global npm package alone does not disable the deployed copy.

For ZIP installations, replace both `canvas_reader.js` and `canvas_reader/` with the new release files, retain your settings, and restart Typora.

For source installations, update, rebuild, and repeat the installation command; see the [development guide](docs/DEVELOPMENT.md). Pulling source or restarting alone does not update the deployed runtime. After a Typora or framework update, check that the extension remains in the target directory.

To disable, use the same resource directory as installation. Windows users using the default path can omit `--resources`:

```bash
typora-canvas --uninstall
```

For a custom resource directory, append the original `--resources` path; source users can use `npm run uninstall:typora --` in place of the CLI. This disables the configuration after restart, retaining plugin files and backups. Use the same permission handling as installation if the directory requires it. Avoid enabling another content-truncation plugin at the same time.

## Search

Hybrid mode uses Typora's native search, including its regex option.

The pure Canvas editor and standalone viewer provide a `.*` regex toggle and default to case-insensitive matching. They search source lines and content blocks respectively. Counts represent matching lines/blocks, not individual occurrences. Cross-line/block patterns are not supported. Search runs in a terminable Worker with a 1-second timeout; invalid patterns report an error without blocking the UI. Results are capped at 5,000 lines/blocks.

## Troubleshoot installation and editing

| Symptom | What to check |
| --- | --- |
| Installer reports a missing or disabled framework | Check for `plugin/global/core/index.js` in the resource directory and enable the framework's `[global].ENABLE` |
| npm updated but Typora behaves the same | Deploy again with `typora-canvas --mode canvas-editor`, then fully restart Typora |
| Permission denied under `Program Files` | Run deployment from a terminal with write access; confirm paths with `--dry-run` first |
| PowerShell blocks `npm.ps1` | Use `npm.cmd`; source installations can invoke `node scripts/install.mjs` |
| Hybrid mode opens, or automatic opening is disabled | Check the configuration path printed by the installer for `RENDER_MODE = "canvas-editor"` and `AUTO_OPEN = true`, then restart |
| Rendering is incompatible or saving reports a conflict | Press `Esc` to return to native mode; check source recovery copies in `~/.config/typora-canvas/recovery/` |
