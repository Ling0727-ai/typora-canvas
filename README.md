# Typora Canvas

A Canvas rendering plugin for Typora, exploring smooth large-document rendering while gradually improving editing and native feature compatibility.

**Current source: 0.6.12, with hybrid mode and an experimental pure Canvas editor.** The default mode is hybrid. The pure Canvas editor uses its own Markdown source model, layout, caret, and selection, drawing document content into a viewport Canvas. Callouts can reuse local image caches generated by the installed Callouts plugin. Everything stays inside the existing editor pane.

The published **v0.1.0 release is an older, standalone read-only viewer**. It does not include the current editing features.

## Experimental pure Canvas editor

Follow [Installation and updates](#installation-and-updates) to prepare the plugin framework and install a prebuilt release or build from source. Pass `--mode canvas-editor` explicitly to install the editable pure Canvas experiment described here. A first installation without a mode uses hybrid mode.

- Markdown stays in an immutable source text structure. Unknown syntax and existing CRLF line endings survive without rich-text serialization; unsupported rendering does not remove source content.
- Unordered (`-`, `+`, `*`) and ordered (`1.`, `1)`) lists render semantic markers, sequential numbers from the list's starting value, mixed nesting, continuation lines, and hanging indents for wrapped text. Marker colors/styles, item typography, indentation and margins come from theme CSS, including `::marker`. Inline emphasis and math retain their source mappings; editing exposes the original markers, and ordinary list text input does not reparse the whole document.
- Canvas draws text, table cells and borders, the caret, and selections. Only lines near the viewport are laid out. A hidden textarea receives keyboard and IME input for the active editing range; it does not render the document.
- Supports input, selections across lines, clipboard operations, undo/redo, arrow keys, and regular-expression search. IME events and composition undo have regression coverage; individual input methods still need real-world testing.
- A dedicated scrollbar remains visible on the right. The native outline uses Canvas heading data, supports click/Enter navigation, updates after heading edits, and highlights the visible section. Native outline hooks are restored on exit.
- `Ctrl+click` opens Markdown links (`Command+click` on macOS); ordinary clicks edit. Web and relative file links go through Typora. Heading fragments navigate within the Canvas document, including links inside Callout snapshots. Reference-style links are not yet supported.
- Basic headings, bold, italics, links, quotes, and code read heading colors, font sizes, weights, line heights, and paragraph spacing from the current theme. Single and repeated body blank lines remain visible. Blank runs adjacent to headings collapse, leaving heading spacing to the theme. Empty paragraph geometry is sampled from theme CSS. Internal Callout blanks remain; only trailing blanks in each Callout scope collapse. The native plugin preview follows the same rule and supports explicit `<br>` breaks. Source blank lines are never deleted.
- Editing Callouts and ordinary quotes exposes the complete `> ` prefix, including titles, body lines, empty quote lines, and nested quotes. The caret can move before `>`; `Home` followed by `Enter` inserts a line before that quote line. Preview hides the markers.
- Enter continues a nonempty quote with its prefix; splitting a line keeps the prefix on both lines. On a line containing only `>` or `> `, Enter removes the prefix without inserting a newline. Empty nested quotes exit one level. Fenced code retains code input behavior. Each operation is one undo step and preserves CRLF.
- Table arrows navigate cells: up/down move to the same column in an adjacent row, skipping the Markdown separator. Left/right move through text and cross into adjacent cells at cell boundaries. At the outer table boundaries they move into surrounding text. At document boundaries an undoable empty paragraph is created. This also works for tables inside Callouts; `Alt+arrow` still moves entire rows/columns.
- Inline syntax supports formulas inside emphasis, including `**$a$**`, `*$a$*`, `***$a$***`, and formulas within bold prose. Formula source ranges remain clickable. Colors, fonts, weights, and size ratios for emphasis, inline code, and links are sampled separately in paragraphs, headings, and table cells. Formulas use the size and color of their context.
- Supports `---`, `___`, and `***` rules, plus fenced code with language metadata. A separate Worker highlights code using colors sampled from the theme's CodeMirror styles. The language control and fence completion support keyboard selection.
- Inline formulas preview after the closing `$`. Moving inside a formula exposes its source; leaving that range restores preview without leaving the line. Display math supports attached delimiters, multiline `$$…$$`, and `\[…\]`; editing inside expands the source.
- A separate MathJax Worker produces self-contained SVG paths for Canvas. It does not reuse or modify Typora's MathJax globals. Worker startup and queue time do not count toward the 5-second per-formula layout timeout. A failure falls back only for that formula. Timeouts restart the Worker and continue other jobs, retaining completed results without automatic retry loops. Failed multiline formulas retain their complete source; Callout failures are isolated too.
- Display equations occupy their actual SVG height, scaled proportionally when too wide, plus `ceil(font size × 0.65)` above and below. Canvas and Callout previews share this calculation. Fractions, matrices, and multiline environments are not constrained to body line height; display math does not use the inline baseline offset.
- Formula completion invalidates only dependent line layouts; multiple completions coalesce into the next frame. Image/formula caches allow up to 256 entries and 32 MiB of decoded pixels, protecting visible assets. An exhausted budget falls back to source rather than triggering eviction/render loops. Eviction cancels queued work and ignores stale decoding results.
- Basic GFM tables have equal-width columns, borders, headers, alignment, line breaks, and inline math. Editing retains the table structure. Merged cells, HTML tables, and Typora's complete column-width algorithm are not yet supported.
- A table toolbar supports resizing, column alignment, inserting/deleting/moving rows and columns, and deleting a table. Each command edits that table's Markdown in one undo step, preserving surrounding text, Callout prefixes, and formula source. Shrinking removes excess cells; undo restores them.
- `Tab` / `Shift+Tab` switch cells; Tab from the final cell adds a row. Enter moves down in the same column; `Shift+Enter` inserts a rendered `<br>`. `Ctrl+Enter` inserts a row below and `Ctrl+Shift+Enter` leaves the table. `Alt+↑/↓` moves a row and `Alt+←/→` moves a column. The menu can copy the table or format its source. Data rows cannot be inserted above the header or moved into its position. Application shortcuts in the editor also accept Command on macOS.
- Callouts support default/custom titles, nesting, `+`/`-` folding markers, hover previews, formulas, and tables. Types, CSS colors, icons, borders, and spacing come from the installed Callouts module. Titles and body text are styled separately. Legacy aliases `notes`, `importent`, and `definitiion` are recognized. Disabling custom Callouts leaves only the five native alert types.
- Exposed Callout markers support character-based left/right and visual-row up/down navigation. Clicking the icon in a native plugin preview opens the `[!type]` source.
- When Callouts is installed, a separate instance with no registered lifecycle handles a temporary offscreen DOM for a visible Callout. Its title decoration and current CSS pseudo-elements, icons, borders, backgrounds, and spacing are rasterized locally and drawn into Canvas. Editing uses the Canvas source model; leaving the block restores the preview. The original plugin instance, note DOM, and companion repository are not modified.
- Callout snapshots are limited to 8 entries and 32 MiB, with one offscreen capture at a time. Blocks over 300 lines, 60,000 characters, or a 24 MiB pixel budget fall back to basic Canvas Callouts, as do incompatible plugins. Capture does not execute arbitrary other plugins or reproduce Typora's entire block parser. Complex HTML and external icon fonts may differ.
- Theme switches, stylesheet loads, and font loads resample backgrounds, text typography, table header/stripe/border colors, and code styles after transitions settle. Formula, icon, and Callout caches are rebuilt. Inline math shares the text baseline; display math is centered.
- Markdown images decode on demand. Relative paths use the current document's Typora resource root. Image and formula caches have entry and byte limits.
- With the latest `obsidian_images` module installed and enabled, Canvas reuses its parsing, CSS decoration, and attachment lookup for forms such as `![[image.png|C|500]]` and `![[image.svg|500|R]]`, including `C/R/L` alignment and pixel widths. Decoding waits for the asynchronous attachment index without refreshing the native document. Ordinary body images currently require their own source line; Callout snapshots also support images mixed with text. Disabled modules leave wiki-image source intact.
- Theme and image-plugin layout are sampled in a temporary local DOM before drawing, including dimensions, position, and paragraph spacing. Layout responds to theme and width changes. Plugin/Typora resolution precedes generic relative-path handling. General CSS filters, shadows, and borders are not fully reproduced.
- `Ctrl+S` or the save button writes current Markdown through Typora's save API. Input does not reparse a hidden native document; exiting synchronizes source back to Typora. The save bridge was adapted to Windows Typora 1.14; other host versions need verification.
- Recovery source copies are stored under `~/.config/typora-canvas/recovery/`. External/native changes pause write-back and retain recovery copies rather than silently overwriting content.
- Escape returns to native editing. `Ctrl+Alt+Shift+F8` toggles the plugin. Saving in the browser demo downloads Markdown; it does not overwrite the originally selected file.

**Compatibility limits:** arbitrary theme CSS, footnotes, HTML, custom macros, complex tables, and all native plugin syntax are not fully reproduced. Unsupported syntax remains in the source. Callouts require explicit `>` prefixes; Markdown lazy continuation is not fully implemented. Canvas samples common semantic styles and uses browser layout locally for Callouts; it is not a general CSS engine. The first click in a Callout snapshot uses approximate line positioning; subsequent editing uses precise text hit testing. Existing backgrounds inside image files are not recolored by the theme. Other plugins depending on the old DOM need individual adapters. Virtualization currently works by logical source line, so very long lines, structural edits, and large selections may still be expensive.

The pure Canvas editor is an editable prototype, not a complete Typora replacement. Set `RENDER_MODE = "hybrid"` and restart to use hybrid mode as a comparison.

## Hybrid mode behavior

- Starts automatically when a document opens; empty notes remain editable.
- A small status indicator reports preparation, caching, native rendering, editing, or input. It does not mean every block is drawn by Canvas.
- Clicking, selecting, typing, IME input, and undo use the native editor without a mode-switch shortcut.
- Images, formulas, SVGs, diagrams, code editors, and some complex styles stay native.
- Typora applies the theme and custom CSS. Cacheable content uses its actual DOM geometry and computed styles. Content unsuitable for snapshots, such as external fonts, filters, shadows, or animation, stays native.
- `Ctrl+F` / `Ctrl+H` go directly to Typora, including its regular-expression search option.
- `Ctrl+Alt+Shift+F8` toggles the layer. Disabling it prevents immediate reopening on the same document; navigating to another document resumes the configured default.
- Source-code mode unmounts the layer; returning to rendered mode restores it.

Startup checks host readiness immediately and periodically rather than relying on a single file-loaded event. Initial MathJax/layout `fileEdited` events refresh caches instead of disabling the plugin.

## Architecture and practical limits

```text
Typora parsing, math and CSS → editable DOM (document and layout authority)
                              ├─ complex content / interaction → native display
                              └─ static ordinary content → local snapshots → viewport Canvas
Offscreen content → browser content-visibility optimization
```

The hybrid bitmap cache defaults to 24 MiB and at most 128 entries. The Canvas backing store follows the viewport. Content, theme, and size changes invalidate caches; interaction synchronously restores native content. The layer does not rewrite Markdown or replace the editable subtree.

**Hybrid mode is not a fully virtualized editor.** It retains the full DOM and host layout work, and snapshot creation has a cost. It does not accelerate initial parsing or eliminate equation computation; editing restores native rendering. Offscreen size estimates can change unvisited content heights. Performance improvements need measurement in real notes.

Hybrid mode provides a compatibility baseline. The pure Canvas direction is a separate document/selection model, incremental layout, viewport drawing, and hit testing, reusing Markdown and math libraries where appropriate.

## Installation and updates

### Requirements and platform scope

- For ZIP installation, no Git or Node.js is required. The npm CLI needs Node.js; version 22 is recommended (minimum 20). Git is needed only for source builds.
- First install and enable [obgnail/typora_plugin](https://github.com/obgnail/typora_plugin#how-to-use-windowslinux-platform). Verify that its plugins work after restarting Typora. This project's installer installs only the Canvas extension; it does not inject the framework.
- The target must be the **resource directory already containing `plugin/global/core/index.js`**, not the theme directory or the `plugin` directory itself. This is usually the directory containing `window.html`; older versions may use `resources/app`. The installer also checks that the framework's `[global].ENABLE` setting is enabled.

| Platform | Installation | Verification scope |
| --- | --- | --- |
| Windows | Defaults to `C:\Program Files\Typora\resources`; override with `--resources` | CI passes; real host testing has primarily used Windows Typora 1.14 |
| Linux | Pass the existing framework resource directory with `--resources`; the path depends on the package | Build, unit tests, and Chromium CI pass; real Typora testing is still needed |
| macOS | Upstream currently documents Windows/Linux installation; this project has no verified macOS Typora installation procedure | Build, unit tests, and Chromium CI pass; the browser demo is available |

**Passing CI on three operating systems does not establish Typora installation support on all three.** Do not use the Windows default path on macOS or assume that copying files into an application bundle loads the framework.

### Install a prebuilt release (no local compilation)

**ZIP, without Node.js:** download `typora-canvas-v0.6.12.zip` from [Releases](https://github.com/Ling0727-ai/typora-canvas/releases/latest). Extract and copy **both** `canvas_reader.js` and the complete `canvas_reader/` folder into your existing framework's `plugin/` directory. Replace both when updating. Do not create another nested `plugin` folder. Retain a copy of old files/settings; manual copying does not run automatic backups. Enable `[canvas_reader]` using the [configuration example](#enable-and-choose-a-mode) and fully restart Typora. Preserve other plugins' settings in the same file.

**npm, with Node.js but no compilation:**

```bash
npm install -g @ling0727-ai/typora-canvas@latest
typora-canvas --mode canvas-editor --dry-run
typora-canvas --mode canvas-editor
```

The CLI defaults to the Windows resource path. Linux and custom installations must specify their existing framework directory:

```bash
typora-canvas --resources "/actual/resource/directory" --mode canvas-editor --dry-run
typora-canvas --resources "/actual/resource/directory" --mode canvas-editor
```

You can also use `npm install -g ./ling0727-ai-typora-canvas-0.6.12.tgz` with a downloaded archive. The package includes the compiled plugin and a bundled installer, with no runtime npm dependencies or build/install lifecycle scripts. npm installs the command; **run `typora-canvas` explicitly to deploy it to Typora**, then fully restart Typora. Framework prerequisites and directory write permissions still apply. Use `typora-canvas --help`, `--version`, or `--uninstall`; pass the same `--resources` when disabling. Installing a newer `.tgz` updates the CLI; run it again to update Typora's copy. `npm uninstall -g @ling0727-ai/typora-canvas` only removes the CLI, so disable the deployed plugin first if desired.

The public npm package is [`@ling0727-ai/typora-canvas`](https://www.npmjs.com/package/@ling0727-ai/typora-canvas). Use the scoped name; the unscoped `typora-canvas` package is not this distribution. To pin a version, use `@ling0727-ai/typora-canvas@0.6.12`. A release tarball URL remains an alternative, for example `https://github.com/Ling0727-ai/typora-canvas/releases/download/v0.6.12/ling0727-ai-typora-canvas-0.6.12.tgz`. macOS host installation remains unverified as described above. Git and development dependencies are only needed for the source route below; ZIP installation needs neither Git nor Node.js.

### Build from source (optional)

Open a terminal where you want to keep the source:

```bash
git clone https://github.com/Ling0727-ai/typora-canvas.git
cd typora-canvas
npm ci
npm run build
```

The **v0.1.0 GitHub release is the old read-only viewer**, without the current editor. Use v0.6.12 or newer, or `main`, for current features. Alternatively, select a successful commit in [Actions](https://github.com/Ling0727-ai/typora-canvas/actions/workflows/ci.yml) and download its `typora-canvas-<os>` artifact. The `typora-canvas-<os>` artifact contains plugin files; `release-files-<os>` contains the ZIP, npm tarball, and checksums. The source-install commands below require the checkout and build above. ZIP/npm users can skip the source route.

### Windows

Run from the repository directory. Use a terminal with write permission, such as administrator PowerShell, when installing under Program Files:

```powershell
npm run install:typora -- --mode canvas-editor --dry-run
npm run install:typora -- --mode canvas-editor
```

For a custom location, use the same directory in both commands:

```powershell
npm run install:typora -- --resources "D:\Typora\resources" --mode canvas-editor --dry-run
npm run install:typora -- --resources "D:\Typora\resources" --mode canvas-editor
```

If PowerShell blocks `npm.ps1`, use `npm.cmd` instead of `npm`.

### Linux

Replace the example directory with the actual location of your installed plugin framework. `/usr/share/typora/resources` is an example, not an automatically detected path:

```bash
TYPORA_RESOURCES="/usr/share/typora/resources"
test -f "$TYPORA_RESOURCES/plugin/global/core/index.js"
npm run install:typora -- --resources "$TYPORA_RESOURCES" --mode canvas-editor --dry-run
npm run install:typora -- --resources "$TYPORA_RESOURCES" --mode canvas-editor
```

If writing the resource directory requires administrator privileges, install dependencies, build, and check `--dry-run` as your regular user first. Replace only the final installation command with:

```bash
sudo env "HOME=$HOME" "$(command -v node)" scripts/install.mjs --resources "$TYPORA_RESOURCES" --mode canvas-editor
```

Keeping the current user's `HOME` ensures configuration and backups still go to that user's directory. The installer does not elevate itself.

### Enable and choose a mode

`--dry-run` checks the framework, configuration, and build files and prints the selected paths without writing installation files. Once those paths are correct, run without `--dry-run`, save your notes, and **fully quit and reopen Typora**. The installer does not close Typora automatically.

| `--mode` / `RENDER_MODE` | Behavior |
| --- | --- |
| `canvas-editor` | The editable pure Canvas experiment described here |
| `hybrid` | Native editing with static Canvas caching; the first-install default when no mode is specified |
| `canvas` | The early standalone read-only viewer |

On updates, omitting `--mode` preserves an existing `canvas-editor` or `canvas` mode; otherwise it uses `hybrid`. Pass the desired mode explicitly to make the choice clear. An existing `AUTO_OPEN = false` is preserved.

Before installation, backups go to `~/.config/typora-canvas/backups/`. If `~/.config/typora_plugin/settings.user.toml` exists, the installer edits it; otherwise it uses the framework directory's user settings. It does not rewrite Typora's `window.html`.

The installer maintains the `[canvas_reader]` section. For manual changes, edit the existing section in the configuration file printed by the installer; do not add duplicate sections. This example enables the pure Canvas editor:

```toml
[canvas_reader]
ENABLE = true
NAME = "Typora Canvas"
HOTKEY = "ctrl+alt+shift+f8"
AUTO_OPEN = true
RENDER_MODE = "canvas-editor"
CACHE_MB = 24
```

Set `AUTO_OPEN = false` for manual activation. `Ctrl+Alt+Shift+F8` toggles the plugin, and Escape returns from pure Canvas to native editing. `CACHE_MB` controls hybrid caching, not every pure Canvas asset cache.

### Update or disable

For source installations, update from the source repository:

```bash
git pull --ff-only
npm ci
npm run build
```

Then repeat your platform's installation command with the same `--resources` and `--mode`, and fully restart Typora. **Pulling source, editing settings, or restarting alone does not update the installed runtime.** After a Typora or framework update, check that the Canvas extension is still in the target directory.

To disable, use the same resource directory as installation. Windows users using the default path can omit `--resources`:

```bash
npm run uninstall:typora -- --resources "/actual/resource/directory"
```

This disables the configuration after restart, retaining plugin files and backups. Use the same permission handling as installation if the directory requires it. Avoid enabling another content-truncation plugin at the same time.

## Search

Hybrid mode uses Typora's native search, including its regex option.

The pure Canvas editor and standalone viewer provide a `.*` regex toggle and default to case-insensitive matching. They search source lines and content blocks respectively. Counts represent matching lines/blocks, not individual occurrences. Cross-line/block patterns are not supported. Search runs in a terminable Worker with a 1-second timeout; invalid patterns report an error without blocking the UI. Results are capped at 5,000 lines/blocks.

## Browser demo and validation

```bash
npm run dev
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

The local demo retains the standalone Canvas viewer and can open Markdown or generate a stress-test document. Files are read locally and are not uploaded.

Browser tests use Playwright Chromium by default. `PLAYWRIGHT_CHANNEL` (such as `msedge`) or `PLAYWRIGHT_EXECUTABLE_PATH` can select an existing browser.

Regression coverage includes:

- Height indexing, Unicode splitting, Markdown parsing, configuration preservation, auto-start, initial rendering events, and returning from source mode.
- Large-document scrolling, search, regex errors and catastrophic-backtracking timeouts, resizing, and cleanup.
- In-place Chinese input, native undo, IME composition, theme changes, preserved SVG/math/extension DOM, and cache cleanup in a simulated host.
- Pure Canvas source preservation, composition undo, save bridging, external-change conflicts, scrollbars, native outline navigation/editing/highlighting, and restored host hooks.
- Link hit testing for web, relative-file, heading-fragment, and Callout links; formula source mappings within emphasis; sampled theme sizes and colors.
- Actual Obsidian image plugin parsing, asynchronous attachment lookup, body/Callout image dimensions and alignment pixels, and Callout marker navigation/clicking.
- Immediate `\alpha` preview, caret mapping, independent MathJax Worker behavior, multiline fatigue-derivation source, single-formula failure isolation, and stable caches with 100 visible formulas.
- Display equation heights and gaps, no overlap with following content, and fraction/matrix/multiline Callout geometry at 18/28px fonts and 420/900px widths.
- Table rendering, alignment, formulas, toolbar operations, source/CRLF/quote preservation, single-step undo, arrow-key cell navigation, and quote continuation/exit on Enter.
- Bounded drawing and DOM size during 10,000-line editing/scrolling; Callout scopes, aliases, folding, hover previews, plugin opt-out, and light/dark/black-theme pixels.
- Offscreen execution of the real Callouts plugin, visible text pixels, editing/undo, theme invalidation, temporary-DOM cleanup, and unchanged original plugin utilities/document content.
- Code highlighting, language controls, rules, heading styles, blank-line policies, and actual table-background pixels after a single light/dark theme switch.

The demo does not depend on another repository's local path. Default Callout types, colors, and SVG icons are included from `typora-obsidian-callouts`. Inside Typora, installed plugins and theme CSS take priority. To refresh the standalone defaults:

```bash
node scripts/sync-callouts.mjs --source ../typora-obsidian-callouts
```

GitHub Actions runs Node.js 22 unit tests, builds, and Chromium regression tests on Windows, macOS, and Linux. macOS uses Command shortcuts; Windows/Linux use Ctrl. Jobs run independently, so a failure does not cancel other platforms. Push, pull request, and manual triggers are supported. Each platform uploads `browser-results-<os>` (screenshots, metrics, platform information, and failure diagnostics) and `typora-canvas-<os>` (built plugin files), retained for 7 days.

Screenshots and metrics are stored in the ignored `test-output/` directory. These are browser integration and simulated-host tests, **not verification of every editing, math, or theme feature inside real Typora, and not evidence of a hybrid-mode performance gain**. Cross-platform CI does not verify installation and host APIs in Typora on all three systems. Installation still requires the platform's actual framework resource directory. Old drawing samples from a 9,001-block synthetic document are not hybrid-mode performance results.
